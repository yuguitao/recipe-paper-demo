# Recipe Lab · 菜谱研究数据看板 v0.3

一个部署在 GitHub Pages 的中文交互网站：通过全国地图查看可追溯的食材批发报价，通过公开菜谱榜单观察食材与菜谱关注信号，并用透明规则演示推荐怎样随食材偏好、地区和策略变化。

**网站：[Recipe Lab](https://yuguitao.github.io/recipe-paper-demo/)** · **代码：[yuguitao/recipe-paper-demo](https://github.com/yuguitao/recipe-paper-demo)**

## 当前版本提供什么

v0.3 的主看板已接入真实公开报价与两家菜谱平台的榜单快照。每条记录保留来源、原始口径和时间；来源目录分别显示已接入、参考、待授权或无法获取的状态。使用真实来源的数据，不表示来源机构为本网站或推荐方法提供认证。

**推荐区目前仍是可解释的规则模拟，论文模型和真实评估结果尚未接入。** 真实数据、派生统计与示例规则分别标注；界面上的推荐变化不能当作论文算法有效性的实验结果。未填造论文标题、作者、DOI、图表或性能指标，也没有运行作者的 Python 推理服务。

原有“五维偏好与月份情境实验”保留在默认折叠的独立实验区。它继续使用可复现的合成价格、时令标签、热度与示例菜谱属性，不与主看板的真实记录混用。

## 已接入的数据与范围

| 数据 | 实际来源 | 本站展示与派生方式 | 关键限制 |
| --- | --- | --- | --- |
| 食材批发报价 | [商务部商务预报「百家日报」](https://cif.mofcom.gov.cn/cif/seach.fhtml?commdityid=170010) | 市场逐条报价、品类、行情日期、前一期价格；同省同品类日价取已覆盖市场的中位数 | 不是官方省均价或居民零售价；不同品类的市场覆盖不同 |
| 菜谱榜单 | [下厨房「本周最受欢迎」](https://www.xiachufang.com/explore/) | 首页展示顺位、平台所标“七天内做过人数”、公开食材字段 | 周期起讫未披露；顺位、做过人数、搜索量与评分不能混称 |
| 菜谱榜单 | [美食天下「当季最热」](https://home.meishichina.com/show-top-type-recipe.html) | 首页展示顺位、页面收藏人数、公开原料字段 | 实际目标页是当季榜，不能改称周榜；收藏人数统计区间未披露 |
| 食材关注信号 | 从上述两份真实榜单分别派生 | 含某食材的样本菜谱数 ÷ 该平台本次榜单首页菜谱数 | 只代表所采样本，不代表全国搜索、销售或地区消费热度 |

文章来源：商务部网站；数据栏目：商务预报·百家日报。菜谱元数据归各原发布平台及相应作者，网站提供原始链接供核验，不转载完整配方步骤或图片。详细证据、访问规则、字段定义与未接入来源见 [价格来源审计](./price-source-audit.md)、[菜谱与食材信号审计](./popularity-source-audit.md)；地图几何来源见 [MAP-SOURCE.md](./MAP-SOURCE.md)。

首次种子采集发生在 **2026-10-24**，取得的价格行情日期只有 **2026-10-22** 这一天。首版“近 7 天”因此只有 **1 / 7 天真实观测覆盖**；后续数据由成功采集自然积累，不用插值、随机数或前一期价格列拼成七天曲线。本文的首次采集说明是版本记录，当前行情日与样本量以网站实际快照为准。

### 地图与周视图

全国地图可选择省级地区与食材。颜色表示**同来源、同品类、同日的省内已覆盖市场中位数**，同时显示样本市场数量和原始报价；灰色表示没有本期可比报价。一个省有少量报价，不表示已覆盖全省市场。

近 7 天省级统计先计算各个真实观测日的市场样本中位数，再对有数据的日值取简单均值，显示实际样本天数。不同来源、单位、批发/零售口径和规格不混算；缺失日不填充。逐市场周统计则保持同市场、同品类、同口径，只平均已取得的日观测。

原表“前一期价格”保留为核验字段，不据此补造独立日期的历史。部分源表变化率与通常的前日基准公式有差异，因此网站同时保留原表值，并将 `(当日价 - 前一期价) / 前一期价 × 100%` 标为本站计算值，避免悄悄改写来源。

### 食材频次的可复核口径

食材信号只读取列表页的食材字段，按代码中的显式同义词表匹配，每道菜对同一食材最多计一次。每条派生记录保存计数、分母、百分比和来源菜谱 ID；下厨房与美食天下分别计算，不合成为一个没有定义的“全国热度”。

同义词分组用于关注信号，不等于价格规格相同。例如“鸡肉（含鸡翅）”的关注分组不能使用白条鸡价格来代表所有部位；普通牛肉也不能直接套用牛腿肉价格。原始食材名称保留，价格比较只使用可明确匹配的品类。

## 更新机制与动态效果

项目的 [GitHub Actions 工作流](./.github/workflows/pages.yml) 配置为每天 **08:25、17:25（北京时间）**检查公开来源，UTC cron 为 `25 0,9 * * *`。推送到 `main` 或手动运行工作流也会执行采集、数据校验、测试、构建和 Pages 部署。调度可能延迟，成功访问源站也不保证源站当天已经发布新数据。

网页每 **5 分钟**检查一次已经发布的本站快照；“检查最新快照”按钮执行同类检查。**网页检查不会触发原站采集，也不会把旧快照更新成新的市场行情。** 页面用状态动画、更新记录和推荐计算阶段展示真实的加载与计算过程；自动演示改变推荐情境，不制造新的价格或热度。

| 时间字段 | 含义 |
| --- | --- |
| 原始报价日期 `observedDate` | 来源页面标明的市场行情日期 |
| 抓取时间 `fetchedAt` | 本站实际读取来源的时刻 |
| 快照生成时间 `generatedAt` | 更新管线生成发布数据的时刻，不等于每条数据的新行情日 |
| 网页检查时间 | 浏览器检查已发布快照的时刻，不等于上游成功采集 |

榜单如果未披露具体周期起讫，保留 `periodDateKnown: false`、`observedDate: null`，另记获取日期。不能用采集日期补造榜期。

来源失败时，管线保留上次成功记录及其原日期，明确显示陈旧或失败状态；从未取得的数据仍为空。缺报价、缺历史或缺食材字段时，不用零值、全国平均、邻省数据或合成值补齐。历史快照保留最近 30 天，支持逐日积累与核验。

## 真实快照上的推荐模拟

“用这期数据，模拟一次推荐”从当前所选平台榜单挑选候选，结合食材偏好和所选地区的可匹配报价，演示“综合观察、榜单优先、食材偏好优先、本地价格机会”等策略的排序变化。

价格因素仅用于比较**已匹配食材的省内样本价位与同品类全国已覆盖市场样本的相对关系**，不是完整菜谱成本。没有真实用量、部分食材缺报价或规格不一致时，不声称得到了整道菜的采购价。排名、匹配和价格因素的公式与缺失处理在页面中展开可见。

这些是网站规则，不是论文模型推理、医学或营养评估，也不构成真实用户偏好预测的准确率。折叠实验区内的五维贡献分解与规则对照同样属于示例，不能称为论文消融实验。

## 本地查看、采集与构建

直接打开 `index.html` 可查看随项目附带的最近快照与本地交互。离线时不会取得新数据；若要检查 HTTP 快照、查看 JSON 下载链接或验证与线上一致的资源加载，请从项目根目录启动本地静态服务：

```bash
python3 -m http.server 8000
```

随后访问 `http://localhost:8000/`。浏览器不直连原站，公开数据由以下命令在有网络的采集环境中更新：

```bash
python3 scripts/update_data.py
```

无网络验证已有种子数据时，可以运行：

```bash
python3 scripts/update_data.py --from-seeds
```

此命令保留种子中的真实采集时间，不会获取新行情，也不应拿其运行时间冒充来源更新时间。Python 采集与更新脚本使用标准库，需支持当前代码语法的 Python 3.10 或更新版本。

使用支持 `node --test` 的 Node.js 运行测试与构建，无需安装 npm 依赖：

```bash
node --test tests/*.test.mjs
node scripts/build.mjs
```

构建生成：

- `dist/`：静态网站、样式与脚本、地图说明、数据来源说明、当前 JSON 与历史 JSON，用于 Pages 发布。
- `../deliverables/recipe-recommender-prototype.html`：内联样式、脚本与当前快照的独立预览文件，可离线查看当前版本；后续更新和独立 JSON 链接需要相应 HTTP 资源。

构建本身不访问数据源。`data/latest.json` 是当前发布快照，`data/latest.js` 是便于静态页面与离线预览读取的同份快照，`data/history.json` 保存累计历史。测试覆盖数据来源与时间约束、失败保留、缺失处理、周统计及示例推荐逻辑。

## GitHub Pages 部署配置

当前仓库使用 `.github/workflows/pages.yml`。仓库的 **Settings → Pages → Build and deployment → Source** 应选择 **GitHub Actions**。工作流需要 Pages 发布权限，并用仓库内容写权限提交三个公开快照文件，保存定时任务之间的历史；不会写入账号凭据或原始用户偏好。

工作流顺序为：检出 `main` → 检查公开来源 → 运行测试 → 构建 → 提交当前/历史快照 → 部署 `dist/`。可在 [Actions](https://github.com/yuguitao/recipe-paper-demo/actions) 查看实际运行和错误记录。源码使用相对资源路径，适用于仓库子路径站点。

接入来源仍需遵守各站访问规则。当前实现读取 robots、低频访问允许的公开页面；遇到禁止访问、登录或验证要求时停止，不绕过。参考入口和待授权平台不计为当前数据接入。

## 论文接入与后续工作

需要作者提供论文正文、真实推理代码、可公开菜谱样本、维度和约束定义、真实实验结果及固定案例，再将示例规则替换为论文实际支持的推理。真实行情接入与论文算法接入是两项独立工作；本版本尚没有经过论文案例的一致性核验。

GitHub Pages 托管静态文件。轻量推理可以在浏览器运行；需要 Python 服务或较大模型时，应由外部服务提供真实推理，或明确展示有版本的案例回放。建议接口、数据字段及验收标准见 [INTEGRATION.md](./INTEGRATION.md)。论文内容、署名、图表和评估指标在取得原始材料后补充，不自动为作者指定开源许可证。

部署背景可参阅 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)与[自定义部署工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
